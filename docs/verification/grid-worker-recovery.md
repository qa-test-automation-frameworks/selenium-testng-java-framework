# Owned-session Grid worker recovery drill

This is an opt-in hosted experiment. Run **Grid Worker Recovery Drill** with GitHub Actions `workflow_dispatch`; it is not part of the regular browser matrix and it does not target a shared or remote Grid. The manual workflow creates a unique Compose project from the pinned Selenium Hub and Chrome image digests, uses one Chrome slot, checks the effective 2 GiB memory and shared-memory limits, and has an eight-minute job timeout with project-scoped teardown.

The drill first validates the Grid `/status` slot inventory and confirms it starts empty. It sends one `quality-drill-unsupported` request with the hub's five-second session queue timeout and one-second retry interval. Only a structured session-creation failure plus a validated inventory without that browser is `CAPABILITY_UNAVAILABLE`; connection trouble is `GRID_UNREACHABLE`.

For the interruption, the TestNG worker creates one Chrome session through `WebDriverFactory`, visits a harmless local `data:` page, and atomically writes a private receipt before printing its readiness marker. The receipt directory is mode `0700`; the receipt is mode `0600`, and neither is uploaded. The Node harness independently matches the receipt's exact session in the validated Grid inventory, then sends `SIGKILL` only to the detached process group it spawned. It requires the orphan to remain visible before issuing one W3C DELETE for that receipt-authorized session. It rejects stale, mismatched, foreign, or inventory-unavailable receipts and never uses a blanket session delete.

After recovery, the harness runs one normal TestNG control through the framework factory, calls `WebDriverFactory.cleanUpDriver`, and verifies the same one-node Grid has no active sessions. That gives the job at most two successful real Chrome sessions: the interrupted one and the cleanup control. The interruption remains classified as `EXPECTED_WORKER_INTERRUPTION`; it is not reported as a passing native test.

GitHub Actions runs the fake-Grid Node tests as part of pull-request quality gates. They cover inventory-schema rejection, classification, URL boundary checks, receipt age/origin/nonce/source/allowlist validation, exact encoded-session deletion, recovery idempotence, and detached-process-group scoping. These fixtures do not count as the real hosted recovery proof.

The uploaded artifact contains only the allowlisted public summary and a sanitized native disposition. It records source/run/image identities, observed capabilities, BiDi as `not-requested`, phase times, process signal, hashed session identifier, recovery result, counts, limits, and limitations. It never contains the private receipt, raw session ID, raw child output, DOM, or screenshot bytes. The synthetic canary is text in a data page, not a screenshot claim. A failed harness first attempts cleanup only from a valid own receipt, removes the private receipt directory, and then the workflow tears down only its unique Compose project.

This proves bounded recovery in a pinned isolated Grid. It does not establish janitor safety on shared enterprise Grids, browser crash recovery, or correctness under arbitrary network partitions.
